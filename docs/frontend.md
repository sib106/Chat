# Интерфейс

Страница собрана без фреймворков: три файла, никакой сборки. Браузер получает их напрямую от сервера.

## Разметка

[`index.html`](../index.html) состоит из трёх частей:

- **`nav.navbar`** — шапка с названием и ссылками-заглушками.
- **`section.chat`** — окно переписки `#chatWindow` и форма `#chatForm` с полем `#messageInput` и кнопкой `#sendButton`. Первое приветственное сообщение вписано прямо в разметку.
- **`aside.monitor`** — панель монитора: заголовок с индикатором связи `#monitorStatus`, журнал `#monitorLog` и кнопка `#monitorClear`.

Скрипт подключён в конце `<body>`, поэтому к моменту запуска все элементы уже существуют и обходиться без `DOMContentLoaded` безопасно.

## Логика страницы

[`script.js`](../script.js) делится на две независимые половины.

### Переписка


| Функция | Что делает |
|---|---|
| `addMessage(text, type, date, trace)` | создаёт пузырь сообщения, возвращает его элемент |
| `buildTrace(trace)` | собирает раскрывающийся блок «Показать процесс» |
| `loadMessages()` | забирает историю с `GET /api/messages` при открытии страницы |

`type` — это `out` для сообщений пользователя и `in` для ответов агента; при загрузке истории он вычисляется из поля `role`.

Отправка устроена так, чтобы страница не выглядела зависшей, пока агент работает:

1. Сообщение пользователя показывается сразу, поле очищается, кнопка блокируется.
2. Вместо ответа появляется заглушка «Агент думает…» — `addMessage` возвращает элемент, поэтому её легко убрать.
3. Приходит ответ — заглушка удаляется, на её месте появляется сообщение агента вместе с трассировкой.
4. При ошибке вместо ответа показывается текст ошибки, кнопка в любом случае разблокируется в `finally`.

Enter отправляет сообщение, Shift+Enter переносит строку.

### Монитор

Вторая половина файла слушает поток событий:

```js
const events = new EventSource('/api/events');
events.onmessage = (m) => {
    const [text, kind] = describeEvent(JSON.parse(m.data));
    monitorLine(text, kind);
};
```

`describeEvent` превращает событие сервера в строку и её вид: «Шаг 1: запускаю search_wikipedia(…)». Список типов событий — в [HTTP API](api.md#события-потока). Неизвестный тип не ломает панель: он выводится как есть.

`monitorLine` добавляет строку с отметкой времени, прокручивает журнал вниз и держит не больше `MONITOR_LIMIT` (300) строк, удаляя самые старые. Длинные аргументы и результаты инструментов режет `short`.

Индикатор связи переключается обработчиками `events.onopen` и `events.onerror`. Переподключением занимается сам браузер, поэтому после перезапуска сервера надпись «нет связи» через пару секунд снова станет зелёной без перезагрузки страницы.

## Оформление

[`styles.css`](../styles.css) идёт по порядку: шапка, раскладка, окно чата, пузыри сообщений, форма, трассировка, монитор.

- Раскладка двухколоночная: чат растягивается, панель занимает фиксированные 380 пикселей.
- На ширине до 1080 пикселей колонки складываются в столбец — панель уезжает под чат.
- Пузыри различаются классами `message--in` (слева, белый) и `message--out` (справа, зелёный).
- Трассировка свёрнута в `<details>` и набрана мелким моноширинным шрифтом.
- Панель монитора тёмная, строки раскрашены по типу события: жёлтый — инструменты, зелёный — успех, оранжевый — нарушенная проверка, красный — ошибка.

Единственная тонкость: `.main` и `.chat` описаны дважды — в базовой части и ниже, в блоке монитора. Побеждают правила, которые идут позже. При правке раскладки смотрите оба места.
