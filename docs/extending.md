# Как расширять и отлаживать

## Новый инструмент

Инструмент добавляется в трёх местах [`agent.js`](../agent.js).

**1. Описание в `TOOLS`** — это единственное, что видит модель. От формулировки зависит, догадается ли она вызвать инструмент:

```js
  {
    type: 'function',
    function: {
      name: 'read_file',
      description: 'Читает файл проекта и возвращает его текст.',
      parameters: {
        type: 'object',
        properties: { name: { type: 'string', description: 'Имя файла, например server.js' } },
        required: ['name'],
      },
    },
  },
```


**2. Реализация в `TOOL_IMPL`** под тем же именем. Функция может быть асинхронной — в цикле стоит `await`. Возвращайте объект: модель увидит его целиком, поэтому в него полезно класть и данные, и пояснения.

```js
  read_file({ name }) {
    if (!/^[\w.-]+$/.test(name)) return { error: 'Недопустимое имя файла' };
    // ...
  },
```

**3. Правило в `CHECKS`**, если новый источник данных требует дисциплины: например, ссылаться на файл или не отвечать по памяти.

Три вещи стоит помнить:

- **Ошибку возвращайте, а не бросайте.** `{ error: '…' }` модель прочитает и попробует другой путь.
- **Проверяйте аргументы.** Их придумывает модель, а не человек: имя файла, диапазон, адрес — всё может оказаться мусором.
- **Осторожно с инструментами, которые что-то меняют.** Пока все инструменты только читают, худшее последствие подсказки со страницы — испорченный ответ. Инструмент, умеющий писать файлы или отправлять запросы, превращает это в настоящую проблему. См. [«Защита от подсказок»](agent.md#защита-от-подсказок-со-страниц).

## Новая проверка

Правило — это объект с тремя полями. `needed` решает, применимо ли оно, `satisfied` — выполнено ли требование, `hint` попадает модели как замечание при переделке. Оба предиката получают один объект: `{ question, usedTools, answer, sources }`.

```js
  {
    name: 'ответ без файла',
    needed: (ctx) => ctx.usedTools.includes('read_file'),
    satisfied: (ctx) => /\.js|\.md/.test(ctx.answer),
    hint: 'Ты читал файл, но не назвал его. Укажи имя файла в ответе.',
  },
```

Помните про бюджет: каждая переделка тратит шаг из `MAX_STEPS`, а попыток всего две.

## База знаний

Пополняется обычными абзацами в [`knowledge.md`](../knowledge.md). Перезапуск сервера не нужен: файл читается при каждом вызове `search_knowledge`.

Поиск примитивный — совпадение слов длиннее трёх букв, не больше трёх абзацев в ответе. Отсюда два практических следствия:

- **Один абзац — одна тема.** Если в абзаце и порт сервера, и порт Ollama, модель их склеит: в тестах она отвечала «сервер работает на портах 3000 и 11434».
- **Пишите словами, которыми спрашивают.** Абзац про «раздачу статики» не найдётся по запросу «какие файлы отдаёт сервер».

## Другая модель или параметры

Модель задаётся константой `MODEL`, адрес Ollama — `OLLAMA_URL`. Параметры генерации собраны в `callOllama`: `temperature` отвечает за фантазию, `num_ctx` за объём контекста, `num_predict` за длину ответа.

Модель обязана уметь вызывать инструменты — на Ollama это, например, `qwen3`, `llama3.1`, `mistral-nemo`. Проверить, что именно скачано, можно командой `ollama list`.

Если поднять `think: true`, Qwen3 начнёт рассуждать перед ответом: качество вырастет, скорость упадёт.

## Отладка

**Консоль сервера.** Агент пишет туда каждый шаг: время раздумий модели, вызванные инструменты, результат проверки. Сетевые повторы помечены `[web]`.

**Панель монитора.** То же самое, но вживую и в браузере.

**Трассировка под ответом.** «Показать процесс» разворачивает шаги уже завершённого ответа, в том числе после перезагрузки страницы.

**Проверка Ollama.** `ollama ps` показывает, загружена ли модель и работает ли она на видеокарте; `curl http://localhost:11434` отвечает `Ollama is running`.

**Имитация недоступной Википедии.** Переменная `WIKI_API` позволяет проверить, как агент ведёт себя при сбое поиска — он обязан ответить «не знаю», а не сочинить:

```bash
WIKI_API=https://LANG.wikipedia.invalid/w/api.php node server.js
```

**Другой порт**, если 3000 занят:

```bash
PORT=3010 node server.js
```

## Известные ограничения

Список честный, каждый пункт проявлялся на практике.

- **Правила держатся на ключевых словах.** «Ответ по памяти» ловит вопросы, начинающиеся с «кто», «что такое», «когда» и ещё нескольких слов. «Питон — это про змей или язык?» проверка пропустит.
- **Поиск Википедии промахивается.** На запрос «Гидо ван Россум» (с опечаткой) поиск вернул статью про телешоу «Проект „Подиум“». Агент в таком случае честно отвечает «не знаю», но ответа пользователь не получает.
- **Модель не всегда слушается промпта.** Именно поэтому существуют проверки: на вопрос о времени она однажды выдала «14:30» из головы, не вызвав инструмент.
- **Панель монитора общая.** Все вкладки видят события всех пользователей, включая чужие вопросы.
- **Переписка в одном файле.** Никакого разделения по пользователям, при каждой записи файл перечитывается целиком. Трассировки заметно раздувают его.
- **Проект не предназначен для публичного доступа.** Нет авторизации, ограничения частоты запросов и разграничения прав.
- **Ответ приходит целиком.** Из-за `stream: false` надпись «Агент думает…» висит до конца генерации. Потоковый вывод — отдельная задача.
- **Защита от подсказок со страниц частичная.** Она держится на правилах в промпте и на том, что все инструменты только читают.
