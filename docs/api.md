# HTTP API

Сервер [`server.js`](../server.js) слушает порт из переменной `PORT`, по умолчанию 3000.

| Метод и путь | Назначение |
|---|---|
| `GET /` | страница чата |
| `GET /index.html`, `/script.js`, `/styles.css` | статика |
| `GET /api/models` | список моделей полигона |
| `GET /api/messages` | вся переписка |
| `POST /api/messages` | задать вопрос агенту |
| `GET /api/events` | поток событий агента |

Наружу отдаются только файлы из списка `STATIC_FILES`. Любой другой путь получает `404` с телом `{"error":"Not found"}`; `server.js`, `agent.js` и `messages.json` по HTTP недоступны.

## GET /api/models

Список моделей, между которыми переключается полигон. Профили заданы в `agent.js`, а отметка `installed` берётся из Ollama в момент запроса.

```json
{
  "defaultModel": "qwen3:8b",
  "models": [
    { "id": "qwen3:4b", "title": "Qwen3 4B", "note": "быстрая повседневная", "installed": false },
    { "id": "qwen3:8b", "title": "Qwen3 8B", "note": "точка отсчёта", "installed": true }
  ]
}
```

Если Ollama не отвечает, список возвращается всё равно — просто все модели будут помечены как нескачанные.

## GET /api/messages

Возвращает массив сообщений целиком, в порядке добавления.

```json
[
  {
    "id": 1789072854837,
    "role": "user",
    "text": "Кто такой Линус Торвальдс?",
    "createdAt": "2026-09-13T18:20:29.000Z"
  },
  {
    "id": 1789072857231,
    "role": "assistant",
    "text": "Линус Торвальдс — финско-американский программист…",
    "createdAt": "2026-09-13T18:20:31.480Z",
    "model": "qwen3:8b",
    "trace": { "steps": [], "totalMs": 2480, "sources": [], "model": "qwen3:8b" }
  }
]
```

Поля `trace` и `model` есть только у ответов агента. У сообщений, сохранённых до появления ролей, поля `role` может не быть — такие считаются пользовательскими.

## POST /api/messages

Поле `model` необязательное: без него берётся модель по умолчанию. Значение проверяется по списку из `agent.js` — произвольную строку сервер не примет.

Запрос:

```json
{ "text": "Кто такой Линус Торвальдс?", "model": "qwen3:8b" }
```

Ответ `201`:

```json
{
  "message": { "id": 1789072854837, "role": "user", "text": "…", "createdAt": "…" },
  "reply":   { "id": 1789072857231, "role": "assistant", "text": "…", "createdAt": "…", "trace": {} }
}
```

| Код | Когда | Тело |
|---|---|---|
| `201` | агент ответил | `{ message, reply }` |
| `400` | пустой текст, битый JSON или модель вне списка | `{ "error": "Неизвестная модель: gpt-5" }` |
| `502` | агент упал: Ollama недоступна, модель не скачана, пустой ответ | `{ "error": "Агент не ответил: Модель qwen3:4b не скачана…" }` |

Запрос держится открытым всё время работы агента — от секунды до десятков секунд. Вопрос пользователя сохраняется **до** обращения к модели, поэтому при ошибке он останется в переписке без ответа. Тело запроса тяжелее 100 КБ обрывается.

## GET /api/events

Поток Server-Sent Events. Соединение не закрывается; каждое событие приходит строкой вида `data: {…}` с пустой строкой на конце. В начале сервер отправляет `retry: 2000` — указание браузеру переподключаться через две секунды после обрыва.

В браузере читается встроенным `EventSource`, без библиотек:

```js
const events = new EventSource('/api/events');
events.onmessage = (m) => console.log(JSON.parse(m.data));
```

События рассылаются **всем** открытым вкладкам. Историю поток не хранит: вкладка видит только то, что произошло после подключения.

### События потока

У каждого события есть поле `type` и метка времени `at`.

| `type` | Когда | Поля |
|---|---|---|
| `start` | вопрос принят | `question`, `model` |
| `thinking` | пошёл запрос к модели | `step` |
| `llm` | модель ответила | `step`, `ms`, `content`, `toolCalls` |
| `tool-start` | начался вызов инструмента | `step`, `name`, `args` |
| `tool` | инструмент отработал | `step`, `name`, `args`, `result`, `ms` |
| `check` | ответ проверен | `step`, `passed`, `failed` |
| `retry` | ответ отправлен на переделку | `step`, `reasons` |
| `limit` | упёрлись в `MAX_STEPS` | `steps` |
| `done` | ответ готов | `answer`, `totalMs` |
| `error` | агент упал | `message` |

Три типа событий — `llm`, `tool` и `check` — одновременно являются шагами сохраняемой трассировки. Остальные живут только в потоке.

## Формат хранения

`messages.json` — массив тех же объектов, что отдаёт `GET /api/messages`. Файл лежит рядом с сервером, читается целиком при каждой записи и указан в `.gitignore`.

Чтобы начать переписку с чистого листа, остановите сервер и удалите файл — он создастся заново.

Модели передаётся не весь файл: берутся последние `HISTORY_LIMIT` сообщений (20) и только поля `role` и `text`.
